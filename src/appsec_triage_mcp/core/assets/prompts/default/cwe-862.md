## Business-logic authorization review

This is a static review of one concrete endpoint. Read the route handler, the
service it calls, the repository or external client, and the middleware or
policy configuration that protects it. Establish which principal is
authenticated and where authorization is checked for every read, update,
delete, export, and batch operation.

Use `confirmed` only when grounded code shows a reachable sensitive operation
without the required authentication, role, owner, or tenant check. Use
`false_positive` only when the relevant check is visible at the actual sink.
Use `unknown` when the middleware, policy, service, repository, or dynamic
dispatch needed to decide is missing. Do not infer security from a route name,
UUID, login requirement, or client-supplied user identifier. Do not make HTTP
requests or execute commands.
