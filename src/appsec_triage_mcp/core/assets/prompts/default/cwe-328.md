## Business-logic hash review

Determine what the value protects before judging the algorithm. A weak digest
used for a cache key or non-security fingerprint is different from a password,
session token, reset token, signature, or integrity value. For credentials,
check a password-hashing function, per-record salt, work factor, upgrade path,
and verification code. For tokens and signatures, check whether a keyed MAC or
modern signature scheme is required.

Use `confirmed` only when grounded code shows an unsuitable algorithm or
parameters for the security purpose. Use `false_positive` only when the code
and its use establish a safe purpose and construction. Use `unknown` when the
consumer or verification path is not visible. Never treat the function name
alone as proof.
