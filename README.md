# AppSec MCP

AppSec MCP проверяет Git-репозитории и собирает находки сканеров в HTML-отчёт. Если подключить сервер к чату с поддержкой MCP, можно попросить модель разобрать каждую находку по исходному коду. Модель предоставляет ваш чат. Сканеры работают в Linux-контейнере.

- **Хочу отчёт по ссылке на репозиторий** → [Запуск из терминала](#запуск-из-терминала).
- **Хочу понять, какие находки подтвердились** → [Разбор находок в чате](#разбор-находок-в-чате).
- **Хочу получить результат в Telegram или на другом сервере** → [Доставка отчёта](#доставка-отчёта).

## Установка

Основная платформа — **Linux x86-64**. На машине нужны Docker Engine, плагин Docker MCP Gateway и Python 3.11+ с модулем `venv`. Команды выполняются в Bash из корня этого репозитория. [Установка плагина Docker MCP на Linux](https://docs.docker.com/ai/mcp-catalog-and-toolkit/mcp-gateway/)

Для отдельного Docker Engine включите поддержку профилей. Переменную окружения также задайте в терминале или в MCP-клиенте, из которого будете запускать Gateway. [Режим Docker Engine и профили](https://github.com/docker/mcp-gateway#usage)

```bash
export DOCKER_MCP_IN_CONTAINER=1
docker mcp feature enable profiles
docker info >/dev/null
docker mcp profile list
```

Установите клиент и зарегистрируйте сервер в Docker MCP. На первой сборке Docker скачивает сканеры. Строка `Ready:` означает, что профиль `appsec-triage` готов.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e .
.venv/bin/python scripts/setup_docker_mcp.py
```

## Запуск из терминала

Запустите клиент и введите адрес своего Git-репозитория, когда появится приглашение.

```bash
.venv/bin/appsec-scan-projects
```

Можно ввести до трёх адресов одной строкой через запятую. Для каждого проекта сервер подберёт сканеры и подготовит отдельный отчёт. Чтобы использовать только Opengrep, запустите клиент с флагом `--scanners opengrep`.

Скрипт сам запустит Docker MCP Gateway, скачает текущую версию основной ветки каждого проекта и удалит временную копию после сканирования. В конце найдите в терминале строку `HTML:` и откройте указанный файл в браузере. По умолчанию отчёты лежат в `.local/reports/`.

| Файл | Что в нём |
| --- | --- |
| `<проект>-<job_id>.html` | Статус сканеров, найденные проблемы, файлы и строки кода. Каждой находке ещё нужна проверка. |
| `<проект>-<job_id>.json` | Статус задания, сводка и сведения об удалении временной копии. |
| `<проект>-<job_id>.log` | Журнал для диагностики, если задание завершилось с ошибкой или не создало HTML. |

## Разбор находок в чате

После установки добавьте в настройки MCP-клиента сервер с транспортом **stdio**. Для клиентов с конфигурацией `mcpServers` добавьте запись `appsec-triage` в список серверов.

```json
{
  "mcpServers": {
    "appsec-triage": {
      "command": "docker",
      "env": {"DOCKER_MCP_IN_CONTAINER": "1"},
      "args": ["mcp", "gateway", "run", "--profile", "appsec-triage", "--long-lived", "--cpus", "3", "--memory", "8Gb"]
    }
  }
}
```

Переподключите клиент. Чтобы проверить соединение, отправьте в чат **«Покажи доступные сканеры через `appsec_list_scanners`»**. Затем отправьте запрос со своей ссылкой.

> Проверь репозиторий `<адрес вашего репозитория>` через AppSec MCP. Сохрани исходники на время разбора. Для каждой находки примени инструкции триажа и проверь по коду, подтверждается ли срабатывание. В отчёте укажи вердикт, файл, строку и основание. Где данных не хватило, напиши, что осталось проверить. Сохрани итоговый HTML и освободи временную копию проекта.

В этом сценарии клиент запускает скан с `keep_checkout=true`. Модель получает базовую инструкцию, подходящие правила для типа находки и стек проекта. В отчёте `confirmed` означает, что модель нашла подтверждение в коде, `false_positive` — что она нашла основание отклонить срабатывание, а `unknown` — что для решения нужен дополнительный факт. Отчёт чата сохраняется в Docker-томе `appsec-mcp-results`. Чтобы получить его в этой же сессии, попросите чат вернуть HTML или отправить его в настроенный канал.

По умолчанию модель использует профиль `generic`. Если описанные в проекте условия Kubernetes, SSH и TLS действительно относятся к вашему сервису, добавьте в запрос фразу **«Для этого проекта используй `deployment_profile=bundled`»**. [Посмотреть условия профиля](src/appsec_triage_mcp/core/assets/configs/deployment.yaml)

## Доставка отчёта

| Куда | Что настроить один раз | Что добавить к команде запуска |
| --- | --- | --- |
| Telegram | Укажите ID чата и сохраните токен в локальном файле с правами `600`. [Настройка Telegram](docs/usage.md#telegram) | `--telegram` отправит HTML в чат |
| По SSH на другой сервер | Укажите адрес и каталог в `.local/config/scp-targets.json`, добавьте ключ и проверенный `known_hosts`. [Настройка SCP и приватного Git](docs/usage.md#scp-и-приватный-git-по-ssh) | `--scp default` отправит ZIP с отчётом и результатами сканеров |

Оба флага можно использовать вместе. Если разбор шёл в чате, отправьте сообщение **«Отправь итоговый отчёт по этому заданию в Telegram»**.

## Windows

Для Docker Desktop с включённым MCP Toolkit откройте PowerShell из корня репозитория. Пример установки и запуска одного проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\scripts\setup-docker-mcp.ps1
.\.venv\Scripts\appsec-scan-projects.exe
```
